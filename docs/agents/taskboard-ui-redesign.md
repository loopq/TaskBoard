# taskboard UI 重做：纸、墨、印

> 2026-11-11 · 状态：已批准并实施，本机验证通过，见 §7
> 背景：用户认为 Opus 5.5 做的飞书风格版本"做得不好"，把视觉 / 交互的决定权交给本次执行者。
> 前作：[taskboard-feishu-ui-task-id-skill.md](taskboard-feishu-ui-task-id-skill.md) §4（飞书白底蓝）、[taskboard-mobile-create-and-navigation.md](taskboard-mobile-create-and-navigation.md)（手机单列 + 分组选择）。

## 1. 现状诊断（本机起服务灌样例数据后截图，桌面 1440 / 手机 390）

| 问题 | 根因 |
|---|---|
| 四列白卡片浮在白底上，没有层次；空列（等反馈 0）像没加载完 | 画布、列、卡片三层用的是同一个白，只靠 1px 边框区分 |
| 每列底部常驻一个**禁用态**的淡蓝「添加」按钮，整板 4 个废按钮 | 手机修复时把按钮改成常驻，但没区分"有没有内容" |
| 短卡片下面空一块（`min-height: 94px` 硬撑） | 卡片没有固定底栏，有元信息和没元信息的卡高度参差，于是用补丁掩盖 |
| 手机端「待处理 · 3」在下拉框和列头各显示一次 | 列头组件在手机上原样保留，和分组选择器职责重叠 |
| 字体、配色、动效全是默认值，没有记忆点 | 对着飞书截图描，没有自己的设计决定 |

## 2. 设计方向：纸、墨、印（不要底纹）

一句话：**暖白画布 + 墨黑文字和按钮 + 唯一的彩色是朱砂红，只用在"盖章"的地方。**

- **画布**：`#f4f3ef` 暖灰白（呼应 favicon 的米色），列是比画布略深一级的面板，卡片是纯白 + 极轻投影。三层各自分明，空列自然有形状。
- **墨**：主按钮、焦点环、进度条全部是墨黑 `#1b1b1a`，不再用飞书蓝。Markdown 链接保留一个深蓝，只为可识别。
- **印**：朱砂 `#d2402a` 只出现在四处——完成态的 ✓（盖章动画：缩放 + 微旋转落下）、过期截止、「非常紧急」、危险操作。「紧急」用琥珀，其余优先级是灰阶。favicon 本来就是一枚红色「完」字印章，这是现成的品牌线索。
- **字**：中文走系统字体（国内 webfont 不可靠，这条约束不变）。拉丁字 wordmark 用 `ui-serif`（Apple 上是 New York）给一点编辑感；数字一律 `ui-monospace` 等宽。零字体文件，CSP 不用动。
- **动效**：首屏卡片错位淡入（`--i` 延迟）、抽屉弹簧滑入 + 背景模糊、完成盖章、菜单缩放淡入。`prefers-reduced-motion` 继续全关。

不做：暗色模式（token 已经集中，后续一个文件的事）、webfont、列表视图、搜索、主题切换。

## 3. 改动清单

### 3.1 `style.css`：token 重写 + 全部视觉
- `:root` 换成上面的色板和 `--radius-card: 10px / --radius-panel: 14px / --col-w: 288px`。
- 删除 `.card { min-height: 94px }` 这个补丁。

### 3.2 卡片 `TaskCard.vue`：消除特殊情况
- **每张卡固定两段**：标题 + 底栏。底栏左侧是元信息 chips（截止 / 优先级 / 子任务 / 评论），右侧是 `#12`。底栏永远渲染（编号保证非空），高度自然一致，不再需要 min-height。
- 已完成的卡：整体 0.6 透明度，底栏显示「昨天完成」（`done_at` 已在数据里，零成本）。
- ✓ 圆圈：18px，选中后朱砂填充，`@keyframes stamp`。
- 首屏错位入场：父组件传 index，`animation-delay: calc(var(--i) * 28ms)`，上限 12 张。

### 3.3 列 `BoardColumn.vue`
- 列头：名称 + 数量药丸；`···` 桌面端 hover 才出现。
- 空列显示虚线占位「拖到这里」/ 已完成空列「完成的任务会收在这里」，替代现在的裸输入框。
- 手机：用 CSS grid 把「新建任务」输入和 `···` 合并成一行（`.col-foot` 占第 1 行第 1 列，`.col-head` 占第 1 行第 2 列，列名 / 数量隐藏）。不动模板结构，不新增组件。

### 3.4 `AddInput.vue`
- 「添加」按钮只在有文字时出现（`v-show`），否则藏起来。提交语义、成功才清空、失败保留草稿的约定一个字不改。

### 3.5 看板 `Board.vue`
- 顶栏：wordmark（serif）+ 日期 + **「过期 1 · 今天 2」**小统计（从 `state.tasks` 算，两行 computed）；右侧头像 + 名字 + 退出图标。
- 手机分组导航：原生 `<select>` 换成横向滚动的分组 chips（名称 + 数量，当前项墨底白字），末尾一个「+」chip 新建分组。纯 CSS/Vue，无依赖；选中值还是 `selectedId`，其余逻辑不动。
- 「+ 新建列」改成一个幽灵列：虚线边框、点击才展开输入。

### 3.6 详情 `TaskDrawer.vue`
- 顶栏：左 `#3`（mono，点击复制链接）+ 所在列名；右：删除、关闭。去掉左上角那个「完成任务」按钮——
- **标题行 = 大号 ✓（24px，和卡片同一个控件）+ 标题**。已完成时标题旁盖一枚旋转 -6° 的朱砂描边「已完成」印章，下面一行「昨天 14:02 完成 · 取消完成」。
- 字段改成属性表：左侧 72px 灰色标签（所在列 / 截止 / 优先级），右侧控件。原来的图标行密而不清。
- 描述、子任务、动态三个分节用统一的小标题样式；动态时间线加一条 1px 竖线把点串起来。
- 底部评论框：无边框卡片式，聚焦时才升起投影。
- 桌面宽 600px，遮罩 `backdrop-filter: blur(6px)`。

### 3.7 首页 `Home.vue`
- 左对齐的编辑式排版：小字日期 → 大号 serif `taskboard.` → 「两个人，各一本。」；两个用户从"卡片"改成两条**书脊式**横条（首字母方块 + 名字 + 锁），点开当前条在原地展开密码框。手机上同样结构竖排。

### 3.8 `Icon.vue`
- 新增：`stamp`（印章）、`inbox`（空列）、`clock`（过期）。其余复用。

## 4. 破坏性分析

- API、数据库、`store.ts` 的写路径：**零改动**。只新增两个只读 computed（过期 / 今天数量）。
- `sortable.ts`、拖拽的 DOM 还原策略不动；卡片列表**不加** `TransitionGroup`（会和 Sortable 的 DOM 搬运打架）。
- `AddInput` 的提交 / 清空 / 失败保留约定不变，只是按钮可见性跟随内容。
- CSP `style-src 'self'` 不动：所有动态样式走 Vue `:style`（CSSOM），和现状一致。
- 手机断点仍是 640px，单列 + 保留组件实例切组不丢草稿的机制不动。
- `?t=12` 直达、复制链接、`skills/taskboard` CLI 不受影响。

## 7. 执行记录（2026-11-11）

改动只在 `web/`（11 个文件），API / 数据库 / store 写路径零改动。与 §3 的两处偏差：

- 卡片盖章动画起初看不见：`complete()` 是乐观更新，卡片瞬间换列重新挂载，`stamping` 状态随之丢失。改为**先在原地盖章 380ms 再调 `complete()`**，期间 `aria-pressed` 用 `done || stamping` 撑住视觉；再点一次被 `stamping` 守卫挡住，不会双发。
- 「新建列」幽灵列缩到 220px，不占整列宽度。

验证（生产构建 + API 自托管，CSP 生效）：

- `npm run build`（vue-tsc + vite）通过。
- Playwright e2e 15 步，**Chromium 15/15、WebKit 15/15**（WebKit 跳过拖拽——Playwright 在 WebKit 不模拟原生 DnD）：回车新建（提交按钮 `display:none` 时隐式提交仍有效）、按钮新建且看板不横向偏移、原地盖章后进「已完成」、已完成详情的印章与时间、取消完成回原列、截止「今天」+ 优先级同步到卡片底栏、Esc 关抽屉、拖拽跨列、列菜单、幽灵列建组、手机 chips 切组、手机 `···` 与输入框同行（量 boundingBox）、手机空列 / 已完成列 / 新建分组切换 / 按钮新建、首页选人与错密码提示。
- 控制台：Chromium 只有首页测试故意输错密码的一条 401；WebKit 关掉截图后同样只剩这条 401——**应用自身零 CSP 违规**。WebKit 带截图时的 16 条「Refused to apply a stylesheet」= 截图次数，是 Playwright 截图注入样式触发的，和上一轮文档记录一致。
- 两条排查结论，留给以后的人：① e2e 里看板横向偏移 36px 是 Playwright 在「添加」按钮 180ms `pop-in` 动画中点击、命中检测失败后强行 scrollIntoView 造成，等动画停稳再点就没有；② Playwright `dragTo` 一步到位喂不出连续 `dragover`，Sortable 不落位，要分步 `mouse.move`。
- §1 的五个问题逐条复核：三层分明 ✓；禁用「添加」按钮消失 ✓；`min-height` 补丁删除、卡片两段结构 ✓；手机列名不再重复 ✓；serif wordmark / 朱砂 / 盖章 / 错位入场 ✓。
- 未覆盖：iPhone 真机、第三方中文输入法、主屏 PWA 的 safe-area 实际表现，仍需用户实测。
